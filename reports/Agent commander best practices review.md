# Agent-commander out-guards the field, then over-documents itself

By the standards the industry settled on in 2025–2026, agent-commander gets the hard part right and several easy parts wrong. On the hard part, putting a human in a position to notice and answer a blocked agent without being lied to, it beats most first-party and third-party tools. It binds each answer to the question's content and re-checks it against the live pane. It pushes only on a real transition into "waiting". It refuses to show an inferred state as a reported one. And no other tool reviewed attaches to tmux in a way that cannot resize a pane. The gaps are elsewhere. The supervision model has no "finished, ready for review" state, no diff or CI evidence and no completion channel, yet the field now treats review as the bottleneck. The security perimeter has four concrete holes: the origin gate ignores ports, the default tokenless server trusts any local process that omits `Origin`, the session cookie *is* the long-lived master token, and there are no anti-framing headers. Answering a dangerous permission prompt takes one tap with no step-up, and nothing logs who approved what. The repository's agent conventions are where the over-engineering sits. Executable invariants, generator-drift tests and a once-per-tree Stop gate are ahead of common practice. But roughly **50–60k tokens** of narrative instructions load into every session, about 16× Anthropic's 200-line target, and parts of them have already drifted from the code they describe. The highest-value fixes are cheap: exact-origin matching, a default token, an opaque per-device session, security headers, step-up for dangerous approvals, and an always-loaded file cut to an index.

## The 2026 consensus: isolate agents, triage by need, supervise evidence rather than activity

By October 2026 every major vendor shipped a fleet surface: Claude Code's agent view, Remote Control and cloud sessions; OpenAI's Codex app and Codex mobile; Cursor 3; GitHub Agent HQ; and Zed's parallel agents. They share one recipe. Each agent gets its own worktree or sandbox and a check it can run on itself, and sessions are triaged in the order needs-input, ready-for-review, working, done. Claude Code's agent view groups sessions as **Pinned → Ready for review → Needs input → Working → Completed**. Its machine-readable `state` field separates `done` from `blocked` and `failed`, and "a session that finished its turn and is waiting for the next instruction reads `done`, not `blocked`" ([Agent view](https://code.claude.com/docs/en/agent-view)). Anthropic's best-practices guide makes verification the precondition for leaving an agent unwatched: "Give Claude a check it can run… It's the difference between a session you watch and one you walk away from", and "Have Claude show evidence rather than asserting success" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)).

Two kinds of evidence explain why the industry converged on fewer interruptions at higher stakes. The first is that per-action approval decays into rubber-stamping. Anthropic reports that users approve **93%** of permission prompts ([Anthropic: auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode)). In a vendor-run study of 1,053 testers, humans caught only **13.6%** of injected dangerous commands, falling from about 17% early in a session to about **5% after 50+ prompts**, while plans were rejected 39% of the time against 3% for individual permission requests ([Claude blog: auto mode default](https://claude.com/blog/auto-mode-default-in-claude-code)). Anthropic says it plainly: requiring humans to approve every action "will create friction without necessarily producing safety benefits" ([Measuring agent autonomy](https://www.anthropic.com/research/measuring-agent-autonomy)). The second is that human review, not generation, now limits throughput. Faros AI telemetry on high-adoption teams shows **PR review time up 91%** and PR size up 154%, with no organisation-level DORA improvement ([Faros AI](https://www.faros.ai/blog/ai-software-engineering)). Agent PRs produced textual merge conflicts **27.7%** of the time, rising to 41.7% between co-active agents of different kinds ([AgenticFlict, arXiv 2604.03551](https://arxiv.org/abs/2604.03551)). The failures that do the most damage are quiet ones: inaccurate self-reporting is a growing share of misalignment across 20,574 sessions ([arXiv 2605.29442](https://arxiv.org/abs/2605.29442)). Supervisors in interview studies rely on proxies, with "test results stand[ing] in for code correctness" ([arXiv 2606.05391](https://arxiv.org/abs/2606.05391)).

Measured against that consensus, agent-commander is strong on the half it chose. The status rail is a fixed glyph column: a raised hand for waiting, a turning arc for working, a ring for idle, a struck ring for a gone pane. It answers "which of these needs me" by position. INV-11 forbids drawing the hand over an inferred status and forbids the arc from filling, because nothing measures progress ([INVARIANTS.md INV-11](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/INVARIANTS.md#L1104)). Agent view writes a Haiku-generated summary on each row. agent-commander instead quotes the last human prompt that named something and composes no text of its own. Given the rise of inaccurate self-reporting, that is a defensible and arguably better choice. The other half is missing. A session that has finished its turn reads `idle`, the same as one that was never prompted. The server never runs `git`, so there is no diff stat, no PR or CI colour and no "last test command and its exit code" ([audit §7, spawn.rs/env.rs](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/src/env.rs#L20-L21)). Nothing warns that five live sessions share one checkout, which is the setup that produces conflicts. The app is tuned for the moment an agent blocks, while the evidence says throughput is lost at the moment an agent finishes.

Notifications follow the same pattern. agent-commander's push is the highest-precision trigger class. It fires only on a non-inferred transition into `waiting`. The first frame counts as backlog, a standing block never re-fires, and nothing is pushed while any browser tab reports itself visible ([push.rs L119–148](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/src/push.rs#L119-L148)). That matches Remote Control's "Push when actions required" toggle, and it fits both the interruption research and Mitchell Hashimoto's argument that humans should choose when to switch context. Three gaps remain. First, there is no low-priority "finished" or "failed" channel, although agent view, Remote Control and Happy all have one ([Remote Control](https://code.claude.com/docs/en/remote-control)). Second, presence means only "a dashboard tab is visible", not terminal focus. So a user typing in tmux still gets pushed, the opposite of the Remote Control behaviour the module cites as precedent; Remote Control also accepts a screen-lock presence file. Third, there is no coalescing, cooldown or quiet hours. Every ntfy push goes out at `Priority: high`, so three agents blocking within a minute produce three high-priority alerts ([push.rs L192–207](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/src/push.rs#L192-L207)).

## The answer path is best-in-class; the perimeter around it has four holes

The core approval mechanism is ahead of first-party practice in one respect. Anthropic's channel permission relay binds a remote verdict to a random five-letter ID that Claude Code issued. The ID binds no content, and the relay neutralises bidi and invisible characters before showing the command ([Channels reference](https://code.claude.com/docs/en/channels-reference)). agent-commander binds by content instead. The prompt ID is a SHA-1 over the session, tool, question, detail, option labels, set position and sandbox flag. Before a digit is typed, the server re-reads the transcript, refuses if the agent is not `waiting`, and checks that the pane numbers that label in that row ([types.rs L527–557](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/src/types.rs#L527-L557); [routes.rs L1978–2036](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/src/routes.rs#L1978-L2036)). This was paid for in the field. At Claude Code 2.1.269 the hard-coded dialog strings drifted, and "only option 1 was answerable, on every permission prompt" until rows began to be read off the pane ([TODO.md §12](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/TODO.md#L322-L368)). The pane check turned that drift into a refusal rather than a mis-typed approval, which is exactly the job of a guard. What the relay has and agent-commander lacks is the absence of a time-of-check/time-of-use gap: agent-commander types after a capture, never inside an open request. It also lacks character sanitisation, since grep finds no bidi or invisible-character handling on the card path.

The weakness is what a single tap can now approve. Since v2.1.283, auto mode is Claude Code's default starting mode ([Permission modes](https://code.claude.com/docs/en/permission-modes)). Routine prompts therefore vanish, and what still reaches a human is concentrated on the riskiest leftovers: explicit ask rules, protected-path writes, classifier fallbacks and critical-path `rm`. In auto mode Claude Code shows the critical-path `rm` prompt only in the terminal, with a countdown, and "wherever Claude Code can't show you a terminal prompt, it denies the command immediately". agent-commander types into the tmux pane, so to Claude Code it *is* the terminal. It can therefore approve from a phone a deletion Anthropic deliberately kept off remote surfaces, with one digit and no step-up ([AnswerCard.tsx L203–246](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/src/web/components/AnswerCard.tsx#L203-L246)). OWASP's agentic Top 10 names this scenario ASI09, human–agent trust exploitation, and recommends a fresh MFA challenge before irreversible actions ([Cycode on OWASP Agentic Top 10](https://cycode.com/blog/owasp-top-10-agentic-applications/)). Remote Control's Trusted Devices re-prompt for a passkey after 18 hours ([Remote Control](https://code.claude.com/docs/en/remote-control)). The card already shows the whole command and a sandbox-escape note, which is the right display. It needs friction to match.

Adversarial verification against a running mock server confirmed four perimeter defects ([claim verification](file:///home/user/agent-commander/research_notes/Agent%20commander%20best%20practices%20review/claim_verification.md)).

**The origin gate compares hostnames, not origins.** `named_host` discards the port, and `is_loopback_name` accepts every 127/8 address. The tokenless server served the fleet and a full transcript, and accepted an answer and a model change, from `Origin: http://127.0.0.1:9999`. It returned 403 only for foreign domains ([routes.rs L468–505](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/src/routes.rs#L468-L505)). This has the same shape as webpack-dev-server's CVE-2025-30360, which allowed a whole category of origins ([Miggo](https://www.miggo.io/vulnerability-database/cve/CVE-2025-30360)). Chrome's Local Network Access does not help, because "`loopback` -> anything" is exempt ([WICG LNA explainer](https://github.com/WICG/local-network-access/blob/main/explainer.md)).

**The tokenless default grants all four powers to any local client that omits `Origin`.** Those powers are read, respond, drive and spawn ([routes.rs L737–740](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/src/routes.rs#L737-L740)). That includes other OS users, since TCP loopback is not per-user the way tmux's 0700 socket is. It also includes the supervised agents themselves. Claude Code's classifier blocks an agent "sending keystrokes to Claude Code's own tmux pane", but a `curl` to agent-commander achieves the same thing by another route. Anthropic's sandbox docs warn that an unauthenticated localhost service "can then act for the command outside the sandbox" ([Sandboxing](https://code.claude.com/docs/en/sandboxing)).

**The `ac_session` cookie's value is the 128-bit token itself, valid for 30 days.** Cookies are not port-isolated, and RFC 6265bis says servers "SHOULD NOT" store security-sensitive data in cookies while running mutually distrusting services on other ports ([RFC 6265bis](https://github.com/httpwg/http-extensions/blob/main/draft-ietf-httpbis-rfc6265bis.md)). In practice every other service on 127.0.0.1 receives the master token, and revocation is global.

**No CSP, `X-Frame-Options` or `frame-ancestors` header is set.** `tower-http`'s `set-header` feature is declared and never wired in, so the tokenless page can be framed ([rust/Cargo.toml L18](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/Cargo.toml#L18)).

The post-CVE consensus fix set, which MCP Inspector 0.14.1 and the Claude Code IDE extension 1.0.24 both shipped, is exact Origin and Host matching plus authentication that is always required ([Datadog on CVE-2025-52882](https://securitylabs.datadoghq.com/articles/claude-mcp-cve-2025-52882/)). agent-commander has the Host half, rebinding protection and constant-time comparison. It stops one step short on each of the other two.

Some flagged items need calibrating, and several smaller ones are real. The spawn dialog offers all six permission modes ([types.rs L914–917](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/src/types.rs#L914-L917)). Of those, **`dontAsk` is not a hazard**: it is a restrictive CI mode that denies anything not pre-approved. Only `bypassPermissions`, which Anthropic says belongs in "isolated containers and VMs only" ([Permission modes](https://code.claude.com/docs/en/permission-modes)), deserves a warning and confirmation, and today it gets a plain `<select>`. The app has no audit log at all, roughly 29 print statements and no logging crate, so "did I approve that from my phone?" cannot be answered after an incident. Claude Code's own cloud sessions log every operation ([Security](https://code.claude.com/docs/en/security)).

Push payloads stay out of transcript text, which is good. They still send agent names (often derived from prompts), session IDs and the tailnet hostname to ntfy.sh or Telegram. On ntfy.sh, "the topic is essentially a password", and anyone who knows it can also *publish* a forged push with an arbitrary click URL ([ntfy publish docs](https://github.com/binwiederhier/ntfy/blob/main/docs/publish.md)).

Robustness and the supply chain lag too. There are **108** non-test `lock().unwrap()` calls under `panic = "abort"`, so any panic kills the whole server, and launchd restarts it on macOS only ([rust/Cargo.toml L47–52](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/Cargo.toml#L47-L52)). CI pins every action to a mutable tag, `ci.yml` has no `permissions:` block, and neither workflow runs CodeQL, `cargo audit`/`deny`, `npm audit` or dependency review ([ci.yml](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/.github/workflows/ci.yml)). GitHub reported **3 Dependabot vulnerabilities (1 high, 2 moderate)** on the default branch at push time. Two Dependabot PRs, for vitest and undici, have sat open since September and October ([PR #5](https://github.com/ziweiwu/agent-commander/pull/5); [PR #2](https://github.com/ziweiwu/agent-commander/pull/2)). The alert details could not be read from this session (HTTP 403), so the mapping of alerts to packages is unverified. The npm package has no runtime dependencies, which suggests the npm alerts hit the dev and build toolchain rather than shipped code, but that should be confirmed. The publish workflow, by contrast, is a model to copy: OIDC trusted publishing, least-privilege tokens and tarball mode checks.

## The defensible niche is real, but it rests on six undocumented Claude Code surfaces

The H1 2026 die-off shows what happens to tools whose value first-party products absorb. Terragon shut down in January, Crystal was deprecated in February, Omnara pivoted, and Vibe Kanban's company shut down in April. That happened just as Remote Control, agent view and the Codex app shipped ([fleet landscape](https://github.com/BloopAI/vibe-kanban); [terragon-oss](https://github.com/terragon-labs/terragon-oss)). Omnara's stated reason is a direct warning: a CLI wrapper "became unfeasible to maintain with Claude Code's constant updates" ([yepanywhere survey](https://github.com/kzahel/yepanywhere/blob/main/docs/competitive/all-projects.md)). agent-commander's architecture is the one the field converged on, where execution stays local and the phone is a window. Its differentiators survive first-party absorption.

The first is zero-intrusion discovery of *every* live interactive session. Agent view lists only background sessions, Desktop "doesn't see… sessions you started from the terminal CLI", and Remote Control needs each session to opt in ([Agent view](https://code.claude.com/docs/en/agent-view); [Desktop](https://code.claude.com/docs/en/desktop)). The second is that nothing passes through a vendor relay; Remote Control stores transcripts on Anthropic's servers. The third is auth-agnosticism: Remote Control does not support API keys, Bedrock or gateways ([Remote Control](https://code.claude.com/docs/en/remote-control)). The fourth is that driving the unmodified CLI sits squarely on the permitted side of Anthropic's rule against third-party subscription routing ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)). And INV-1 appears to be unique. Claude Squad captures panes for previews, but it attaches a PTY that it explicitly resizes ([claude-squad tmux.go](https://github.com/smtg-ai/claude-squad/blob/main/session/tmux/tmux.go)). No reviewed tool documents a design like agent-commander's control-mode client, which never sends `refresh-client -C`. That matters while Claude Code's tmux rendering-corruption bug draws 70 reactions ([anthropics/claude-code#29937](https://github.com/anthropics/claude-code/issues/29937)).

The structural risk is the Omnara risk. agent-commander observes through `~/.claude/sessions/<pid>.json`, transcript JSONL shapes, subagent sidecars, `claude agents --json`, rendered dialog strings and slash-command timing. Each was checked by hand against a named 2.x version, recorded only in comments, with no version gating and no canary. The one interface it consumes that Anthropic calls supported, `claude agents --json`, is in research preview and its fields "may change" ([Agent view](https://code.claude.com/docs/en/agent-view)).

INV-5 promises that if the session file changes shape, "agents must still list from `claude agents --json`". The verification confirmed that this fallback **does not exist**. The CLI output contributes only a set of IDs used to filter ghosts. Renaming `sessionId`, `pid` or `cwd` would empty the fleet, and so would renaming `sessionId` in the CLI output ([registry.rs L195–198, L296–307](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/src/registry.rs#L195-L307)). That is a written invariant contradicted by the code, in the file whose stated purpose is to stop exactly that.

Meanwhile the documented, push-based channels go unused. Claude Code exposes 33 hook events, among them `Notification` with `permission_prompt`/`agent_completed` types, `StopFailure`, and a `PermissionRequest` hook that can answer a prompt from inside the process ([Hooks](https://code.claude.com/docs/en/hooks)). It also exports OpenTelemetry events, including a `blocked_on_user` span, with content redacted by default ([Monitoring](https://code.claude.com/docs/en/monitoring-usage)). Rejecting hooks as the *primary* source is reasonable, since zero intrusion is the product. But hooks and OTel are not even discussed as an optional corroborating source, and an opt-in `PermissionRequest` path would remove the time-of-check gap altogether.

## The repository's executable conventions are ahead of practice, and its prose layer is the over-engineering

Several of the repository's conventions are things the evidence says to do, done better than most repositories manage. Invariants are numbered and greppable from test names on both sides of the wire. A guard test fails on an invariant with no test carrying its number, and on a cited test file that does not exist ([test/invariants.test.ts](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/test/invariants.test.ts#L72-L160)). Three generators and the ts-rs wire contract are held to their committed output by drift tests. INV-2's delivery guarantees are a proptest state machine. Illegal states are made unrepresentable as types: `WithinRoot`, `SendableKey`, `Prepared`/`Failed`. Mock mode runs on separate ports and refuses the production port. And "say which gates you ran" is an explicit norm. This is the "executable specification" and "linters validate the knowledge base" pattern from OpenAI's harness-engineering write-up ([secondary summary](https://zby.github.io/commonplace/sources/harness-engineering-leveraging-codex-agent-first-world/)). It matches Anthropic's dictum that "anything that must happen every time belongs in a hook" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)). The Stop gate "blocks at most once per tree state", which is stricter loop protection than Claude Code's built-in `stop_hook_active` flag plus its 8-continuation cap ([Hooks](https://code.claude.com/docs/en/hooks)). TODO.md's decision to defer Kani and reject TLA+, with measured reasons, is the kind of restraint the rest of the prose lacks.

The prose layer contradicts every vendor's guidance. `CLAUDE.md` imports AGENTS.md (808 lines) and INVARIANTS.md (2,476 lines): **3,286 lines, 34,423 words, about 50–60k tokens**, loaded into every session and every non-Explore subagent, and re-injected after compaction. That is about 16× Anthropic's "under 200 lines per CLAUDE.md", and Anthropic says plainly that "imports… don't reduce its context cost" ([Claude Code memory](https://code.claude.com/docs/en/memory)). GitHub's own instruction-generation prompt caps instructions at two pages. OpenAI's team abandoned "one big AGENTS.md" for a roughly 100-line map. Codex truncates AGENTS.md at **32 KiB** ([openai/codex agents_md.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/agents_md.rs)), which here falls around line 526 of 808. Any Codex agent therefore never sees the "Commits" section, including "Commit or push only when asked".

The controlled evidence says the cost is real even if the dollars are small. Context files raised success only about 4 points at up to +19% cost, and "unnecessary requirements… make tasks harder" ([ETH, arXiv 2602.11988](https://arxiv.org/abs/2602.11988)). Instruction-following degrades in the 100–250-instruction regime, and these files contain about 200 explicit must/never/always tokens ([IFScale, arXiv 2507.11538](https://arxiv.org/abs/2507.11538)). Accuracy falls with input length even on trivial tasks ([Chroma context-rot](https://github.com/chroma-core/context-rot)). AGENTS.md's 40-entry "Things that have already bitten" section, 54% of the file, shows every smell in the June 2026 catalogue. That catalogue measured context bloat in 42% of popular repos, skill leakage in 35% and init fossilization in 24% ([arXiv 2606.15828](https://arxiv.org/abs/2606.15828)). In this file, launchd restart procedures, npm-publish history, Kiro and Node-backend narratives, and "measured on 2026-09-06 at load average 8.7" all sit in always-loaded rules.

Volume has also defeated the drift guards. The always-loaded files contain claims that are now false. Three documents tell agents to "reach for" `old-node-backend-branch`, which does not exist on the remote ([AGENTS.md L53–55](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/AGENTS.md#L53-L55)). AGENTS.md says the token "is still printed in full by `announce`", but the code masks it to four characters ([routes.rs L3059–3075](https://github.com/ziweiwu/agent-commander/blob/a69ffe58bc269d02d236aa4c9e2583920ffa0070/rust/src/routes.rs#L3059-L3075)). INV-5's CLI fallback is fictional, as shown above. INVARIANTS.md names ten Node-era identifiers, such as `assertSlashCommandable`, `checkSpawnRequest` and `buildFrame`, that appear nowhere in the code. Test counts disagree across five documents, and `rust/README.md` still calls the shipping server "parked". The guard resolves test citations, not prose. So the more prose there is, the larger the unguarded surface, which is the "rapid rot" failure OpenAI reported.

The machinery that makes the claims trustworthy also cannot be reproduced. The Stop hook, the pre-commit hook and both review agents live in an external `harness` plugin that the repo neither declares nor says where to obtain. There is no SessionStart hook, so a fresh cloud session without `node_modules` cannot pass its own gates. Two known-flaky tests sit inside the gate: `token.test.tsx` failed 3 of 6 runs on a clean main. ImpossibleBench shows Claude's characteristic shortcut under an unsatisfiable check is editing the test ([arXiv 2510.20270](https://arxiv.org/abs/2510.20270)). The commit rule "never add a Co-Authored-By: Claude trailer" is enforced by prose that competes with Claude Code's built-in attribution guidance. Anthropic's documented fix is the `attribution`/`includeGitInstructions` settings ([Claude Code memory](https://code.claude.com/docs/en/memory)). In this very research session, the harness injected a reminder to *add* such a trailer, and only a precedence clause kept the project rule on top.

## Prioritized improvements

The ordering below weighs exploitability and user harm first, then cost. Most P0 items are a day's work each.

| Priority | Change | Why (evidence) |
|---|---|---|
| P0 | Match full origins (scheme+host+port) against the server's own; add a test that a different-port loopback Origin is refused | Verified bypass from any loopback port; CVE-2025-30360 shape |
| P0 | Make `--token auto` the default even on loopback; require it for non-browser clients | Closes no-Origin access by other users and by supervised agents; MCP Inspector moved to "auth required" |
| P0 | Replace the token-valued cookie with an opaque, server-mapped per-device session (shorter life, `__Host-` on HTTPS, per-device revoke) | RFC 6265bis port-isolation warning; global revocation today |
| P0 | Wire `tower-http` headers: `frame-ancestors 'none'`/`X-Frame-Options: DENY`, a CSP, `nosniff`, `Referrer-Policy` | Feature already declared, unused |
| P0 | Triage the 3 Dependabot alerts; merge or close PRs #2/#5; add `dependabot.yml` covering npm, cargo and github-actions | 1 high, 2 moderate open on main |
| P1 | Step-up for dangerous approvals: confirm (WebAuthn where available) on critical-path `rm`, `dangerouslyDisableSandbox`, protected paths and "don't ask again" options; never auto-latch these | OWASP ASI09; 13.6% → ~5% human catch rate; auto mode makes remaining prompts the risky ones |
| P1 | Append-only audit log: who (session or device) answered, pasted, spawned or keyed what, when | No record exists; Anthropic logs every cloud-session operation |
| P1 | Warn and confirm on spawning `bypassPermissions` (leave `dontAsk` alone) | Vendor: containers/VMs only |
| P1 | Neutralise bidi, invisible and lookalike characters on the answer card; keep head and tail of long commands | Parity with Claude Code's relay |
| P1 | SHA-pin actions, add `permissions:` and `timeout-minutes` to `ci.yml`, run `cargo audit`/`cargo deny` and `npm audit --omit=dev` | No scanning today |
| P1 | Cut always-loaded context to a roughly 150-line AGENTS.md (commands, port rules, INV-1/2, generated-files and `cargo.sh` rules, commit rules first) plus a ~50-line INV index (number → one-line rule → test selector); move essays to on-demand docs, path-scoped `.claude/rules/`, skills (launchd, mac bundle, publish) or HTML comments | 16× over vendor target; Codex truncation; ETH/IFScale evidence |
| P1 | Fix the false claims: implement or delete INV-5's fallback, fix the branch reference (point to commit a05da3c), the token-masking line, the Node identifiers and the counts; run `/doctor prompt-audit` in CI | Drift in the contract file itself |
| P2 | Add `ready for review` (finished turn since last human input) and `failed` (`StopFailure`/`api_error`) states; show diff stat, last test command plus exit code, and PR/CI colour | Field-wide triage order; supervisors use tests as proxies |

Some things should stay exactly as they are: INV-1's control-mode design; content-bound, pane-verified answers; transition-only push with a minimal payload; INV-11's refusal to compose or infer; the invariant-to-test guard; drift tests; mock ports; and the publish workflow. Two of the recommendations above cut against the repo's own instincts. First, the cure for prose drift is less prose, not more guards. Second, one-tap answering, the feature built for phones, is exactly where a little friction belongs.

## Conclusion

The central finding is an inversion. agent-commander applies extreme epistemic discipline to what it *shows* the human: it never claims done, never infers waiting, and verifies every answer against the pane. It applies far less to what it *trusts*: any loopback port, any local process, a 30-day master-token cookie, a one-tap approval of a home-directory delete. The same pattern shows in its conventions. Its executable checks are ahead of the field, while its narrative layer grew past what any guard can keep true, to the point of asserting a fallback that does not exist. Both point to the same correction: carry the rigor the project already shows in its tests and types into its perimeter and its documentation.

Strategically, the window is defined by first-party gaps rather than permanent advantages. Agent view ignores interactive sessions, Remote Control needs opt-in, a subscription and a vendor relay, and neither guarantees a pane is never resized. If Anthropic extends agent view to interactive sessions with a web surface, the "see everything" pitch narrows to self-hosting, auth-agnosticism and verified answering. The best way to deepen that moat is not more invariants. It is to move up the supervision loop toward review: finished-work evidence, diffs and CI. That is where the 2026 evidence says human attention is actually spent.
