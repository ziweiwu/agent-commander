# Landscape of tools for managing, monitoring and controlling multiple AI coding-agent sessions (Claude Code focus), as of October 2026

Method note (applies to every section): star counts, creation dates, last-push dates, licenses and archived flags were read from the GitHub search API on 2026-10-02 and are point-in-time. README claims are the project's own (marketing unless the mechanism is described). news.ycombinator.com, cursor.com, github.blog, zed.dev (web), docs.warp.dev, conductor.build and thenewstack.io were blocked by this environment's egress proxy, so claims about Conductor, Cursor 3, GitHub Agent HQ and HN threads come from secondary sources or search snippets and are labelled as such. Anthropic's own docs (code.claude.com) and the GitHub repos (via raw.githubusercontent.com) were read directly.

## Q1. Which tools exist and what is their status in 2026?

### Takeaway
The category had a wave of shutdowns, deprecations and pivots in H1 2026 (Terragon shut down Jan 16, Crystal deprecated Feb, Omnara pivoted away from being a Claude Code client, Bloop/Vibe Kanban shut down Apr 10, CodMate archiving, coder/agentapi and claude-code-webui archived), exactly as Anthropic, OpenAI, Cursor, GitHub and Zed shipped first-party multi-session surfaces (Remote Control Feb, Codex app Feb 2, Cursor 3 Apr 2, Zed Parallel Agents Apr 22, Claude Code agent view May 11, Codex in ChatGPT mobile May 14). The surviving high-traction third-party tools are mostly multi-vendor workspaces (Superset, cmux, Emdash, Nimbalyst), mobile relays (Happy, CloudCLI), GUIs (opcode) and a long tail of terminal/TUI, hooks-based and notifier tools.

### Inferences
- The die-off clusters in Jan–Apr 2026, i.e. right as first-party parallel/mobile surfaces shipped; tools whose whole value was "a mobile remote for Claude Code" (Omnara v1) or "a cloud runner for Claude Code" (Terragon) were the first casualties. Wrapping the CLI is a maintenance liability (Omnara's stated reason), and free OSS orchestrators struggle to monetize (Bloop's stated reason).
- Star counts are now dominated by multi-vendor workspaces created or relaunched in late 2025–2026 (cmux, Superset), not by Claude-only tools.

## Q2. How does each tool observe and control sessions, and what does it offer (isolation, review, approvals, notifications, mobile, cost, history, license, platform, pricing)?

### Takeaway
Almost every third-party tool either spawns the agent itself (inside its own PTY, tmux session, wrapper or SDK process) or observes passively through hooks or transcript files; very few both observe sessions they did not start and drive the live TUI. Worktree isolation, diff review and status badges are near-universal among orchestrators; phone access is either via a vendor/cloud relay (Happy, RC, Codex mobile, Nexting, Superset Pro) or self-hosted web over Tailscale/LAN (CloudCLI, Claude Code Viewer, agent-deck web).

### Cited Findings

**First-party: Anthropic**
- Agent view lists only *background* sessions: "Interactive sessions you have open in other terminals don't appear until you background them"; a separate supervisor/daemon runs background sessions (state in `~/.claude/jobs/<id>/`, `~/.claude/daemon/roster.json`); states Working / Needs input / Idle / Completed / Failed / Stopped; peek panel lets you reply without attaching, but permission dialogs need an attach ("When nobody is attached, these commands can't open their dialogs… Attach and run the command again"); PR labels with CI colour; background sessions isolated in `.claude/worktrees/` by default; notifications via terminal channel and `Notification` hook types `agent_needs_input`/`agent_completed`; subagents and teammates "aren't listed as separate rows"; the doc describes no remote/mobile surface for agent view itself (background sessions "run on your machine") — [agent view doc](https://code.claude.com/docs/en/agent-view)
- `claude agents --json` "Prints active sessions as a JSON array… every live session, plus background sessions that are still working or blocked", with fields `cwd, kind (interactive/background), startedAt, id, state, pid, status, waitingFor, sessionId, name`; Anthropic recommends it over reading `~/.claude/jobs/` — [agent view doc](https://code.claude.com/docs/en/agent-view)
- Remote Control: connects claude.ai/code or the Claude iOS/Android app to a session running locally; three modes — server mode `claude remote-control` (multiple sessions, `--spawn same-dir|worktree|session`, `--capacity` default 32), `claude --remote-control`, or `/remote-control` from inside an existing session; optional auto-connect for every interactive session (`remoteControlAtStartup`); outbound HTTPS only, "registers with the Anthropic API and polls for work"; Pro/Max/Team/Enterprise only, "API keys are not supported"; not available on Amazon Bedrock, Google Cloud's Agent Platform or Microsoft Foundry, when `ANTHROPIC_BASE_URL` points at an LLM gateway/proxy, when signing in through an enterprise Claude apps gateway, or when `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`/`DISABLE_GROWTHBOOK` is set; "One remote session per interactive process" outside server mode; "Local process must keep running… start it inside tmux or screen" — [Remote Control doc](https://code.claude.com/docs/en/remote-control)
- RC mobile push: `/config` → "Push when actions required for permission prompts and questions"; permission prompts and AskUserQuestion stay open until answered; diff pane on connected devices; Trusted Devices option — [Remote Control doc](https://code.claude.com/docs/en/remote-control)
- Away-from-terminal matrix in the official docs: Dispatch (message a task from the mobile app; runs on your machine via Desktop), Remote Control, Channels (push events from Telegram/Discord/iMessage or your own server into a CLI session), Slack, self-hosted environments, scheduled tasks — [Remote Control doc](https://code.claude.com/docs/en/remote-control)
- Desktop Code tab: sidebar of parallel sessions filterable by status/project/environment; worktree per session; local, cloud, SSH or WSL environments; diff review then PR with CI status bar (auto-fix/auto-merge, polls via `gh`); OS notification when a session finishes and you are not viewing it; Claude can "check on, message, or archive your other sessions" but "sees only the sessions the desktop app runs itself… doesn't see cloud sessions, or sessions you started from the terminal CLI or the VS Code extension"; Dispatch sessions get a push "when it finishes or needs your approval"; Dispatch requires Pro or Max (not Team/Enterprise) — [Desktop doc](https://code.claude.com/docs/en/desktop)

**Auth/billing constraints that shape mechanisms**
- Anthropic: "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users"; Agent SDK products "should use API key authentication"; this "does not… prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription" — [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Claude Code Viewer made chat sending, resume, permission approval and AskUserQuestion opt-in because "As of April 2026, Anthropic's Terms of Service prohibit using the Agent SDK to send chat messages with a subscription account" (project's interpretation; it adds the boundary "remains ambiguous") — [README](https://github.com/d-kimuson/claude-code-viewer)
- Anthropic announced on May 13, 2026 that Agent SDK and `claude -p` usage would move to a separate monthly credit (Pro $20, Max 5x $100, Max 20x $200) from June 15, then confirmed on June 15–16 the change "is no longer happening" for now — [digitalapplied](https://www.digitalapplied.com/blog/anthropic-claude-credit-overhaul-june-15-2026); [claudefa.st](https://claudefa.st/blog/guide/development/agent-sdk-credit); [Tech Times](https://www.techtimes.com/articles/317625/20260602/anthropic-ends-subscription-subsidy-agents-june-15-credit-pool-replaces-flat-rate-access.htm). Contradiction: termic's README still says the vendor SDK "bills against a separate credit pool as of June 2026" — [termic README](https://github.com/simion/termic)

### Inferences
- Four observation mechanisms dominate: (1) own the process (PTY/tmux/wrapper: Claude Squad, CCManager, Superset, cmux, Happy, VibeTunnel); (2) hooks/plugins writing to a socket or server (Warp, Emdash, vibe-notch, MioIsland, disler, agents-observe); (3) transcript/file watching (CloudCLI, Claude Code Viewer, AgentHub, abtop, Kibitz, opcode, Agent Sessions); (4) vendor relay APIs (Remote Control, Codex mobile). agent-commander combines (3) with process discovery (`~/.claude/sessions/<pid>.json`, `claude agents --json`) and drives the real TUI through tmux, which is rare.
- Driving the unmodified interactive CLI (tmux send-keys) sits on the clearly-permitted side of Anthropic's credential rule and is untouched by any future SDK-credit split, while Agent-SDK-based GUIs carry policy and billing uncertainty. This is a durable positioning point for agent-commander.

### Gaps
- Exact mechanisms for Happy's "remote mode", Conductor's agent runtime, Lucarne's discovery and Nexting's attach are undocumented in what could be read.
- Licenses for VibeTunnel, codeg, AgentHub, Kibitz and Jean were not verified.
- No reliable usage/download/MAU numbers beyond GitHub stars; pricing is verified only for Superset's tiering (Pro needed for mobile) and, second-hand, for Conductor.

## Q3. Which features are table stakes vs differentiators, and what do users request or complain about?

### Takeaway
By October 2026 the table stakes are parallel sessions, worktree isolation, a state list (working / needs input / idle / done), needs-input notifications, diff review with PR/CI, and multi-agent support (Claude Code plus Codex at minimum), with phone access becoming expected now that Anthropic, OpenAI, Cursor and GitHub all ship it. Differentiators that remain: answering structured dialogs safely from a phone, zero-intrusion observation of sessions you already started, terminal-faithful views, self-hosting with no relay, subagent/delegation visibility, and cost/context/quota awareness. The loudest demand signals are push-on-approval, reliable reconnects, always-on persistence and better tmux/multiplexer behaviour.

### Cited Findings
- Agent view ships the "state list" pattern first-party: groups "Pinned · Ready for review · Needs input · Working · Completed", PR labels, worktree isolation, notifications — [agent view doc](https://code.claude.com/docs/en/agent-view)
- The worktree + diff + PR loop is present in Claude Squad, CCManager, Superset, Emdash, Nimbalyst, Vibe Kanban, AgentHub, codeg, Sculptor, the Codex app, Cursor 3, Zed and Claude Desktop — [Claude Squad](https://github.com/smtg-ai/claude-squad); [Superset](https://github.com/superset-sh/superset); [Emdash](https://github.com/generalaction/emdash); [Desktop doc](https://code.claude.com/docs/en/desktop); [Zed parallel agents](https://github.com/zed-industries/zed/blob/main/docs/src/ai/parallel-agents.md)
- Multi-vendor support is now the norm in descriptions: Claude Squad ("Claude Code, Codex, OpenCode, and Amp"), CCManager (8 CLIs), agent-deck, Superset ("100+ coding agents"), Emdash, cmux, Agent Sessions (16 formats) — [Claude Squad](https://github.com/smtg-ai/claude-squad); [CCManager](https://github.com/kbwo/ccmanager); [agent-deck](https://github.com/asheshgoplani/agent-deck); [Superset](https://github.com/superset-sh/superset); [Agent Sessions](https://github.com/jazzyalex/agent-sessions)

- The RC issue list (reconnects, sessions missing from the list, wanting always-on) suggests first-party reliability gaps that a local, server-side observer can fill, at least for now.

### Gaps
- Reddit (r/ClaudeAI, r/ChatGPTCoding) threads were not reached in depth, and HN comment bodies were blocked, so complaint evidence leans on GitHub issues and READMEs.
- No survey data ranks features by user importance.

## Q4. What is the risk that first-party offerings absorb the category, and what do third-party tools still do better?

### Takeaway
Risk is high for single-vendor parallel orchestrators and "phone remote for one session" apps: Anthropic now ships agent view (local multi-session list with reply-from-peek), Remote Control with push for approvals, Desktop parallel sessions with worktrees and PR monitoring, Dispatch, Channels and cloud sessions; OpenAI, Cursor, GitHub and Zed ship equivalents. Third parties still win on cross-vendor scope, zero-intrusion observation of every existing interactive session, terminal-native/tmux workflows, self-hosting without a vendor relay, auth-agnosticism (API-key and enterprise-gateway users), Linux/headless hosts, and deeper observability (subagents, quota, cost).

### Cited Findings
- Agent view covers dispatch, monitoring and replies "without keeping a terminal attached" — but only for background sessions, needs an attach for permission dialogs, does not list subagents as rows, and has no remote/mobile surface — [agent view doc](https://code.claude.com/docs/en/agent-view)
- Remote Control needs a claude.ai subscription ("API keys are not supported") and an Owner toggle on Team/Enterprise, and it is unavailable on Bedrock / Agent Platform / Foundry, behind an `ANTHROPIC_BASE_URL` LLM gateway or proxy, or through an enterprise Claude apps gateway; one remote session per interactive process unless in server mode; local process must stay running; server mode gives up after ~10 minutes offline; non-permission dialogs forwarded remotely expire after five minutes by default — [RC doc](https://code.claude.com/docs/en/remote-control)
- RC can be made near-universal: auto-connect "for every interactive session" via `/config` or `remoteControlAtStartup` — [RC doc](https://code.claude.com/docs/en/remote-control)
- Desktop cannot see CLI-started sessions ("doesn't see… sessions you started from the terminal CLI or the VS Code extension"); Dispatch is not available on Team or Enterprise — [Desktop doc](https://code.claude.com/docs/en/desktop)
- Codex mobile reached all ChatGPT plans including Free and Go (preview, 2026-05-14) — [TechRadar](https://www.techradar.com/pro/a-new-rhythm-for-collaboration-is-emerging-openai-adds-remote-access-to-bring-codex-to-chatgpt-for-iphone-ipad-and-android)
- Cursor 3 and Zed both put parallel agents with worktrees and a status sidebar inside the editor; Zed hosts Claude through ACP — [digitalapplied](https://www.digitalapplied.com/blog/cursor-3-agents-window-complete-guide); [Zed external agents](https://github.com/zed-industries/zed/blob/main/docs/src/ai/external-agents.md)
- GitHub Agent HQ runs Claude, Codex and Copilot side by side across github.com, GitHub Mobile and VS Code (Copilot Pro+/Enterprise, preview Feb 2026) — [InfoWorld](https://www.infoworld.com/article/4130352/github-previews-support-for-claude-and-codex-coding-agents.html)
- Third-party survivors explicitly position against first-party gaps: CloudCLI vs RC ("All your sessions, not just one"), termic vs Conductor ("real CLIs… no vendor backend"), cmux ("a primitive, not a solution"), Lucarne ("Zero-intrusion"), Session Kit (per-session accounts; "talks to no server of mine") — [CloudCLI](https://github.com/siteboon/claudecodeui); [termic](https://github.com/simion/termic); [cmux](https://github.com/manaflow-ai/cmux); [Lucarne](https://github.com/tuchg/Lucarne); [Session Kit](https://github.com/dob323/session-kit)
- Business fragility of third parties: Bloop (Vibe Kanban) and Terragon shut down; Omnara pivoted to compete with Claude Managed Agents — [Goodbye bloop](https://www.vibekanban.com/blog/shutdown); [terragon-oss](https://github.com/terragon-labs/terragon-oss); [omnara](https://github.com/omnara-ai/omnara)
- Anthropic forbids third-party Claude.ai login and routing on users' subscription credentials, and "reserves the right to take measures to enforce these restrictions… without prior notice" — [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)

### Inferences
- What first-party has absorbed (2026): "see all my Claude sessions and which need me" (agent view, for background sessions), "answer/approve from my phone" (RC + push), "parallel worktree sessions with diff/PR" (Desktop, Codex app, Cursor 3, Zed), and "start work from my phone" (Dispatch, Codex mobile, RC server mode).
- Defensible ground for agent-commander: (1) it shows *every* live interactive session, including ones started in plain terminals without RC turned on, which no first-party surface lists in a UI (only `claude agents --json` exposes them); (2) its tmux capture is read-only and never resizes panes; (3) it is self-hosted over Tailscale with a token, so prompts and transcripts never transit a vendor relay; (4) it works with any auth mode, including API keys and gateways where RC is unavailable; (5) it adds delegation trees and context/cost per card; (6) ntfy/Telegram pushes work without the Claude app. The biggest single threat is Anthropic extending agent view to interactive sessions plus a web/mobile surface (RC auto-connect already gets close), and the biggest structural risk is reliance on undocumented internals (`~/.claude/sessions/*.json`, transcript formats), which Omnara's experience shows can break under rapid CLI releases.
- Cross-vendor reach (Codex, OpenCode) is a lever agent-commander has deliberately not pulled (it removed Kiro); most surviving third parties lead with it.

### Gaps
- No public roadmap from Anthropic on extending agent view to interactive sessions or to the web/mobile apps was found.
- Pricing pressure (e.g. whether Conductor Pro or Superset Pro retain users after first-party mobile) is not measurable from public data.

## Q5. Does any other tool observe pre-existing Claude Code sessions it did not spawn? Does any avoid resizing tmux panes or offer read-only capture?

### Takeaway
Several tools observe sessions they did not start, but almost all do it read-only (abtop, AgentHub, Agent Sessions, CodMate) or by resuming transcripts in their own process (CloudCLI, Claude Code Viewer, opcode), or need hooks installed first (vibe-notch, MioIsland, disler, agents-observe, Claude-Code-Remote). Kibitz and Claude-Code-Remote are the closest to "drive a live session you did not launch", and Claude-Code-Remote does it by tmux injection. Claude Squad uses `capture-pane` for its preview but attaches a resizable PTY client. No reviewed tool documents a guarantee that it never resizes a pane, or a control-mode-client capture design like agent-commander's INV-1.

### Cited Findings
- abtop discovers Claude Code, Codex and OpenCode sessions "from local process/file state" and only focuses the agent's existing terminal on `Enter` (cmux, tmux, iTerm2) — read-only — [README](https://github.com/graykode/abtop)
- AgentHub watches sessions "via file-system watchers (no polling)"; to interact it opens its own embedded SwiftTerm PTY to resume — [README](https://github.com/jamesrochabrun/AgentHub)
- Kibitz watches active Claude/Codex sessions and can "dispatch prompts to existing or new sessions" (mechanism not documented in the README) — [README](https://github.com/kibitzsh/kibitz)
- CloudCLI: "all your existing sessions are discovered automatically" from `~/.claude` — [README](https://github.com/siteboon/claudecodeui); Claude Code Viewer reads `~/.claude` logs for "real-time conversation log viewing", with resume/send/approve now opt-in and going through the Agent SDK — [README](https://github.com/d-kimuson/claude-code-viewer); opcode auto-detects `~/.claude` and browses `~/.claude/projects/` — [README](https://github.com/winfunc/opcode)
- Claude-Code-Remote: hooks for notifications plus "Seamless command injection into active tmux sessions" and "Full terminal output capture" — [README](https://github.com/JessyTsui/Claude-Code-Remote)
- Hooks-based observers see any session once hooks are installed in user config: vibe-notch (`~/.claude/hooks/` → Unix socket, approve/deny) — [README](https://github.com/farouqaldori/vibe-notch); Emdash installs "marker-tagged entries in the agent's user-level config" — [README](https://github.com/generalaction/emdash); Warp's plugin emits OSC 777 from hooks — [claude-code-warp](https://github.com/warpdotdev/claude-code-warp)
- Lucarne claims to show "agents currently running on this machine" with "no hooks, no skills, no MCP" — [README](https://github.com/tuchg/Lucarne)
- First-party: `claude agents --json` lists "every live session" with `kind` interactive/background, but the agent view UI excludes interactive sessions until they are backgrounded; RC attaches to an existing session only from inside it (`/remote-control`) or via auto-connect — [agent view doc](https://code.claude.com/docs/en/agent-view); [RC doc](https://code.claude.com/docs/en/remote-control)
- Spawn-only tools (do not adopt pre-existing sessions): Claude Squad (`tmux new-session … <program>`) — [tmux.go](https://github.com/smtg-ai/claude-squad/blob/main/session/tmux/tmux.go); Happy (must start via `happy` wrapper) — [README](https://github.com/slopus/happy); VibeTunnel (must start via `vt`) — [README](https://github.com/amantus-ai/vibetunnel); CCManager, Superset, Emdash, cmux, Nimbalyst, Conductor (own the terminal or runtime) — [CCManager](https://github.com/kbwo/ccmanager); [Superset](https://github.com/superset-sh/superset)
- tmux capture vs resizing: Claude Squad renders its preview with `tmux capture-pane -p -e -J` (and a ranged `-S/-E` variant) but keeps "a PTY… running the tmux attach command. This can be resized" and calls `pty.Setsize` on window changes — [tmux.go](https://github.com/smtg-ai/claude-squad/blob/main/session/tmux/tmux.go); one Claude Squad issue reports "TMUX error capturing pane content" — [#189](https://github.com/smtg-ai/claude-squad/issues/189)
- Anthropic's own docs suggest tmux/screen to keep a Remote Control session alive over SSH ("start it inside tmux or screen"), i.e. tmux remains the substrate even for first-party remote access — [RC doc](https://code.claude.com/docs/en/remote-control)

### Inferences
- agent-commander's combination appears unique among reviewed tools: discovering every live interactive Claude Code session from session files and `claude agents --json` without wrappers or hooks; rendering the pane via a non-sizing tmux control-mode client with `capture-pane` polling; and typing into the real TUI (send-keys/paste-buffer) with server-side guards — plus phone answering of structured dialogs that is transcript-bound and pane-verified.
- Closest functional neighbours, by axis: observation breadth — abtop (read-only TUI), Kibitz; live control of existing tmux sessions — Claude-Code-Remote; phone UI over Tailscale reading `~/.claude` — Claude Code Viewer, CloudCLI; first-party substitute — RC with auto-connect plus agent view.
- "Never resize a pane" is likely an unclaimed differentiator worth stating publicly, given open tmux rendering-corruption complaints (#29937) and Claude Squad's attach-and-resize design.

### Gaps
- Source code was inspected only for Claude Squad; agent-deck, awslabs CAO, Claude-Code-Remote, Kibitz and Ccmux may also use `capture-pane`, and some might avoid resizing, but their READMEs do not say.
- Whether any tool uses tmux control mode (`tmux -C`) was not verified (no code search was run).
